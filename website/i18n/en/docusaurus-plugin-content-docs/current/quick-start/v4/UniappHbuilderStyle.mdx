Introducing Tailwind CSS into `src/app.css`, this file will serve as the Tailwind CSS entry:

```css title="src/app.css"
@import "tailwindcss";
@source not "unpackage";
@source not "uni_modules";
```

<CssImportReminder />

For IDE smart prompts, you need to explicitly tell `Tailwind CSS IntelliSense` which file is the CSS entry of Tailwind 4 in VS Code. The most direct way is to point it to the actual `src/app.css`:

```json title=".vscode/settings.json"
{
  "tailwindCSS.experimental.configFile": "src/app.css"
}
```

If you prefer to put a separate file "only recognized by the editor", you can also create an additional `src/main.css`:

```css title="src/main.css"
@import "tailwindcss";
@source not "unpackage";
@source not "uni_modules";
```

Then point `experimental.configFile` to it:

```json title=".vscode/settings.json"
{
  "tailwindCSS.experimental.configFile": "src/main.css"
}
```

This `src/main.css` is only used for IntelliSense, do not actually introduce it in `App.vue` / `App.uvue`. The application still uses `src/app.css` as the Tailwind CSS entry when running.

## `@source` Scan range troubleshooting

### Problem phenomenon

If your `uni-app` / `uni-app x` project places third-party plug-ins or dependencies directly on `uni_modules` in the root directory, and Tailwind 4's CSS entry does not explicitly exclude it, then Tailwind 4 may also mistake the dependent source code, README sample text or build product as a candidate, ultimately generating meaningless styles.

### Root cause

The root cause is still that the scan range is too wide. Tailwind 4 will collect candidates based on `@source`. If `uni_modules` is scanned in together, non-business text in the third-party directory will also be included in the extraction scope.

### Recommended configuration

For the `HBuilderX` workflow, it is recommended to explicitly exclude it in the CSS entry of Tailwind 4:

```css title="src/main.css"
@import "tailwindcss";
@source not "unpackage";
@source not "uni_modules";
```

### Best Practices

- `@source` should try to only cover the business source code directory
- Exclude `uni_modules`, `node_modules`, `dist`, `unpackage`, documentation and build products by default
- If you must scan a certain `uni_modules` package, only include exactly the files that actually carry the template class name, do not scan the entire directory

`@import "tailwindcss"` needs to be written here, because the judgment currently used by `tailwindcss-intellisense` to trigger v4 design system loading only recognizes `@import "tailwindcss"` or `@theme {}`, and does not recognize `@import "weapp-tailwindcss/index.css"`.

> `@source not "unpackage";` is added to avoid the infinite loop problem of differential compilation of `HBuilderX`; together with `@source not "uni_modules";`, it can avoid scanning third-party dependent source code into the candidate set of Tailwind 4.
