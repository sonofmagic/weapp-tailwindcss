# uni-app x

<EnvironmentRequirements />

:::tip
Mainline access documentation has been merged into [uni-app x](/docs/quick-start/frameworks/uni-app-x). This page is reserved for legacy links and Tailwind CSS 4-specific troubleshooting.
:::

`weapp-tailwindcss@5` supports Tailwind CSS 4 in HBuilderX uni-app x projects. The repository's local HBuilderX E2E suite covers the Web, WeChat Mini Program, Android, iOS, HarmonyOS, and consecutive arbitrary-value class additions through Web HMR.

:::info local verification
HBuilderX, developer tools, and App simulators depend on the development machine, so Mini Program and App E2E runs stay local and do not run in CI/CD.

```bash npm2yarn
npm run e2e:hbuilderx:local
npm run e2e:hbuilderx:local:web
npm run e2e:hbuilderx:local:mp
npm run e2e:hbuilderx:local:android
npm run e2e:hbuilderx:local:ios
npm run e2e:hbuilderx:local:harmony
```
:::

## Install

```bash npm2yarn
npm init -y
npm install -D tailwindcss weapp-tailwindcss
```

## Register plugin

Use the `uniAppX` preset for uni-app x. Put the Tailwind CSS 4 entry in a plain `.css` file and pass its absolute path through `cssEntries`.

```ts title="vite.config.ts"
import { dirname, resolve } from 'node:path'
import { fileURLToPath } from 'node:url'
import { defineConfig } from 'vite'
import uni from '@dcloudio/vite-plugin-uni'
import { uniAppX } from 'weapp-tailwindcss/presets'
import { WeappTailwindcss } from 'weapp-tailwindcss/vite'

const projectRoot = dirname(fileURLToPath(import.meta.url))

export default defineConfig({
  plugins: [
    uni(),
    WeappTailwindcss(
      uniAppX({
        base: projectRoot,
        cssEntries: [resolve(projectRoot, 'main.css')],
        rem2rpx: true,
      }),
    ),
  ],
})
```

Do not register `@tailwindcss/postcss` or `@tailwindcss/vite` again. Tailwind generation, class name translation and unit processing under the applet and app targets are all taken over by `weapp-tailwindcss`.

:::info Web and App Debugging Notes
`cssEntries` is used to tell `weapp-tailwindcss` the entry file of Tailwind CSS 4. The entry should still be a real CSS file that HBuilderX / Vite can process. Web/H5, Android and iOS all need to maintain `appType: 'uni-app-x'`. Do not manually close `uniAppX` when running on the web side, otherwise any value class name in the `.uvue` template will not be converted into a safe selector.

`rem2rpx`, `unitsToPx`, and `unitConversion` are top-level options of the `uniAppX()` preset. Do not put them under `cssOptions`.
:::

## Add CSS entry

```css title="main.css"
@import "tailwindcss" source(none);
@source "./App.uvue";
@source "./pages/**/*.{uts,uvue}";
@source "./components/**/*.{uts,uvue}";
@source "./stores/**/*.{uts,uvue}";
@source not "./uni_modules/**/*";
@source not "./unpackage/**/*";
```

`@source` Directory of scripts to override pages, components, and possibly generated class names. Do not put `unpackage` into the scan range, otherwise the HBuilderX product will in turn interfere with the development build.

## Import the entry in App.uvue

`cssEntries` will not automatically add CSS to the HBuilderX / Vite module diagram, it must be actually imported in the global style:

```html title="App.uvue"
<style>
@import './main.css';
</style>
```

In the absence of this import, candidate scans may still succeed, but web, applet, and app pages will not load the generated styles.

## Verify any value class name

Write a minimal use case on any page:

```html
<view class="p-4">
  <text class="bg-[#102938] text-[#f7fbff] w-[173px]">Tailwind CSS 4</text>
</view>
```

After running to the Web, WeChat applet and target App platform in sequence, check whether the element style takes effect. App E2E in the warehouse will also append `bg-[#102938] text-[#f7fbff] w-[173px]` to the page, and then check whether the translated class name appears in the HBuilderX product.

## Layout restrictions

- Do not rely on `uni-app x`, `gap`, `gap-x-*` in `gap-y-*`
- `space-x-*` and `space-y-*` should not be used as cross-terminal spacing solutions.
- The native App text uses `<text>`, and the text-related styles must be written directly on `<text>`
- When a stable spacing across the end is required, directly write `mt-*` / `ml-*` to the sub-item, or encapsulate the spacing component of a fixed structure
