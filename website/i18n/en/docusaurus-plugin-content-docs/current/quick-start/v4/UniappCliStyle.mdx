Introducing Tailwind CSS into `src/app.css`, this file will serve as the Tailwind CSS entry:

```css title="src/app.css"
@import "tailwindcss";
@source not "dist";
@source not "../src/uni_modules";
```

<CssImportReminder />

In order to solve the IDE smart prompt problem, you need to explicitly tell `Tailwind CSS IntelliSense` which file is the CSS entry of Tailwind 4 in VS Code. The most direct way is to point it to the actual `src/app.css`:

```json title=".vscode/settings.json"
{
  "tailwindCSS.experimental.configFile": "src/app.css"
}
```

If you prefer to put a separate file "only recognized by the editor", you can also create an additional `src/main.css`:

```css title="src/main.css"
@import "tailwindcss";
@source not "dist";
@source not "../src/uni_modules";
```

Then point `experimental.configFile` to it:

```json title=".vscode/settings.json"
{
  "tailwindCSS.experimental.configFile": "src/main.css"
}
```

This `src/main.css` is only used for IntelliSense, do not actually introduce it in `App.vue`. The application still uses `src/app.css` as the Tailwind CSS entry when running.

## `@source` Scan range troubleshooting

### Problem phenomenon

If your `uni-app` project puts third-party plug-ins or dependencies under `src/uni_modules`, and the CSS entry of Tailwind 4 does not explicitly exclude this directory, then when scanning the source code, the regular fragments, README sample text or build products in the dependencies may be mistaken as candidates, ultimately generating meaningless styles.

### Root cause

The root cause is that the scanning scope is too wide, and third-party content other than business source code is also included in the extraction scope.

### Recommended configuration

For the `uni-app cli` project, it is recommended to explicitly exclude it in the CSS entry of Tailwind 4:

```css title="src/main.css"
@import "tailwindcss";
@source not "dist";
@source not "../src/uni_modules";
```

### Best Practices

- `@source` should try to only cover the business source code directory
- Exclude `src/uni_modules`, `node_modules`, `dist`, `unpackage`, documentation and build products by default
- If you must scan a certain `uni_modules` package, only include the exact files that actually carry the template class name, do not scan the entire directory

`@import "tailwindcss"` needs to be written here, because the judgment currently used by `tailwindcss-intellisense` to trigger v4 design system loading only recognizes `@import "tailwindcss"` or `@theme {}`, and does not recognize `@import "weapp-tailwindcss/index.css"`.
