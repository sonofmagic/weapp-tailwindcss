#Build and introduce external components

## Preface

In our daily development, we often use and encapsulate various component libraries. Some are open source, UI libraries developed by third parties, and some are UI libraries that our developers encapsulate for their own specific business. Many of these situations are actually based on the popular `Open sourceUILibrary(orforkrevision of)` + `Mainly based on self-encapsulated business components`

`Open sourceUILibrary` Their styles are relatively independent of the entire system. For example, their styles all start with `ant-` and `el-`. Generally, they will not conflict with the styles in the original system after being introduced. However, `Self-encapsulated business components` does not have such problems because it is often highly bound to the system.

So how to use `tailwindcss` to build/publish and introduce your own encapsulated business components?

## Build components

### Core Idea

First of all, I must focus on the core ideas of this article:

`tailwindcss` is just an `css` generator. It just helps you match strings from your source code to generate `css` according to certain rules. So when using it to build components, be sure to think about the scope of influence of `tailwindcss` generated by `css`, because most `tailwindcss` is applied globally by default. But in many cases, your custom styles in components are not necessary.

Based on this core idea, we can know the feasible and unfeasible ways to encapsulate components, roughly as follows:

### Feasible solutions

1. `custom css selector` + `Functions & Directives`
2. `add prefix` (add prefix)
3. `add scoped` (Add custom attributes similar to data-v-[hash] like `vue` and `scoped`, and then modify the css selector)
4. No packaging solution (do not build the product, publish it directly, then install it in the project, then extract the text specified in `node_modules` and regenerate it.)

### Unfeasible solution

1. module css This will modify the css selector.

## Detailed explanation of feasible solutions

Here I wrote 2 `demo`, namely `react` and `vue`. The code below uses `vue` as an example. For an example of `react`, see `BuilddemoLink` below.

### custom css selector + Functions & Directives

This solution is actually very traditional and only uses the functions of `tailwindcss` and `@apply` instructions in `theme`.

For example, we have a component `ApplyButton.vue`. Its template, style and independent `tailwind.config.js` are as follows:

```html
<script setup lang="ts">
</script>

<template>
  <button class="apply-button">ApplyButton</button>
</template>

<style src="./index.css"></style>
```

```css
@config 'tailwind.config.js';
@tailwind utilities;

.apply-button {
  @apply text-white p-4 rounded;
  background-color: theme("colors.sky.600")
}
```

```js
const path = require('node:path')

/** @type {import('tailwindcss').Config} */
export default {
  content: [path.resolve(__dirname, './index.vue')],
  // ...
}
```

Then when packaging, use this file or the export file (`index.ts`) as the packaging entry.

In this way, in its product css, since the selector is defined by you, you can ensure that it is as unique as possible.

Its corresponding `css` product is:

```css
.apply-button {
  border-radius: 0.25rem;
  --tw-bg-opacity: 1;
  background-color: rgb(2 132 199 / var(--tw-bg-opacity));
  padding: 1rem;
  --tw-text-opacity: 1;
  color: rgb(255 255 255 / var(--tw-text-opacity));
}
```

### add prefix

This is also easy to understand. As for prefixes, every UI library does it this way. We can create the following code:

```html
<script setup lang="ts">
</script>

<template>
  <button class="ice-bg-sky-600 ice-text-white ice-p-4 ice-rounded">PrefixButton</button>
</template>

<style>
@config 'tailwind.config.js';
@tailwind utilities;
</style>
```

```js
const path = require('node:path')

/** @type {import('tailwindcss').Config} */
export default {
  prefix: 'ice-',
  content: [path.resolve(__dirname, './index.vue')],
}
```

Its corresponding `css` product is:

```css
.ice-rounded {
  border-radius: 0.25rem;
}
.ice-bg-sky-600 {
  --tw-bg-opacity: 1;
  background-color: rgb(2 132 199 / var(--tw-bg-opacity));
}
.ice-p-4 {
  padding: 1rem;
}
.ice-text-white {
  --tw-text-opacity: 1;
  color: rgb(255 255 255 / var(--tw-text-opacity));
}
```

### add scoped

This is done by adding html tag attributes and modifying the css selector at the same time:

```html
<script setup lang="ts">
</script>

<template>
  <button class="bg-sky-600 text-white p-4 rounded">ScopedButton</button>
</template>

<style scoped>
@config 'tailwind.config.js';
@tailwind utilities;
</style>
```

Here we only add an `style` attribute to `scoped`

```js
const path = require('node:path')

/** @type {import('tailwindcss').Config} */
export default {
  content: [path.resolve(__dirname, './index.vue')],
}
```

`css` generates the result:

```css
.rounded[data-v-10205a53] {
  border-radius: 0.25rem;
}
.bg-sky-600[data-v-10205a53] {
  --tw-bg-opacity: 1;
  background-color: rgb(2 132 199 / var(--tw-bg-opacity));
}
.p-4[data-v-10205a53] {
  padding: 1rem;
}
.text-white[data-v-10205a53] {
  --tw-text-opacity: 1;
  color: rgb(255 255 255 / var(--tw-text-opacity));
}
```

### Not packaged

To summarize the above three methods, they all make component libraries by working on selectors, and they all have a packaging process, that is, `src`->`dist` and then publish `dist`

But this fourth option is different: the core is `Not packed`

That is, after we write the component, we directly point the entry file of `npm` to `src`, and then directly publish the components inside (for example, directly publish the `vue` component)

In this case, you need to let your components in `node_modules` undergo the processing of `js` again, such as `vue sfc compiler`, `babel`, `swc`, etc.

At the same time, you also need to configure `tailwind.config.js` in your project to extract the component source code content in your `node_modules`:

```diff
module.exports = {
  content: [
    './index.html',
    './src/**/*.{html,js,ts,jsx,tsx,vue}',
+   './node_modules/mypkg/src/components/**/*.{html,js,ts,jsx,tsx,vue}'
  ]
}
```

In this way, `css` can be re-extracted and generated in the project main `css chunk`.
